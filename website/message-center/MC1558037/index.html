Microsoft Purview | Data Loss Prevention: Protection for local AI agent interactions

17 November 2026MC1558037 on mc.merill.net ↗Message

In brief

Microsoft Purview Data Loss Prevention is expanding to protect sensitive data in supported local AI agent interactions, allowing administrators to apply DLP policies to agent prompts, responses, and tool interactions. Public preview starts late January 2027, with general availability by late April 2027. No action is required to enable this feature.

Message Center announcement

What and why

Microsoft Purview Data Loss Prevention (DLP) is expanding inline protection to supported local AI agents, helping organizations safeguard sensitive data across human-to-agent and agent-to-tool interactions. Organizations can configure DLP policies with sensitive information type (SIT)-based controls to detect sensitive information in prompt text and files and block policy-violating data movement during prompt processing and at supported tool interaction points.

Rollout schedule

  • Public Preview: We will begin rolling out in late January 2027 and expect to complete by late February 2027.
  • General Availability: We will begin rolling out in late March 2027 and expect to complete by late April 2027.

Impact on your organization

Who is affected

  • Organizations with the required licensing that use Microsoft Purview Data Loss Prevention to protect sensitive information in supported local AI agent interactions

Platforms and services

  • Microsoft Purview Data Loss Prevention
  • Supported local AI agents
  • Custom enterprise applications and devices

What will happen

  • This feature will become available automatically to tenants with the required licensing as it rolls out.
  • Administrators will be able to select a new Agents location in custom enterprise applications and devices DLP policies to scope policies to local agents.
  • Administrators can apply DLP policies to supported local agents to audit and protect agent-to-human and agent-to-tool interactions.

Action required and recommendations

No action is required for the feature to become available to eligible tenants.

We recommend that administrators:

  • Review existing DLP policies and determine whether policies should be scoped to supported local agents.
  • Review the prerequisites before configuring DLP protection for local agent interactions.
  • Determine the appropriate DLP protections for your organization's sensitive information.

Learn more

  • Learn about data loss prevention | Microsoft Learn

Compliance considerations

QuestionAnswer
Does the change alter how existing customer data is processed, stored, or accessed?Yes. DLP protection is expanded to supported local agent interactions, including prompts, responses, files, and tool interactions.
Does the change introduce or significantly modify AI/ML or agent capabilities that interact with or provide access to customer data?Yes. The change adds DLP protection for supported interactions involving local AI agents and enterprise information.
Does the change modify Purview DLP policies or enforcement?Yes. Administrators can scope custom enterprise applications and devices DLP policies to a new Agents location and use DLP policies to audit and protect supported local agent interactions.
Does the change include an admin control?Yes. Administrators configure the protection through Microsoft Purview DLP policies by selecting the Agents location and applying supported DLP controls.
