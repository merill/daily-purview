Sensitivity Labels Sharepoint Default Label

24 November 2026Doc update+16 / −1 lines

In brief

The documentation now explains label inheritance, interactions and precedence between library defaults and content-based auto-labeling policies, troubleshooting for conflicts, and the eligible premium subscription requirement.

What Purview admins need to know

Administrators can use the added guidance to configure labeling expectations, understand overrides, and diagnose auto-labeling conflicts.

  • Default sensitivity label for a document library: Location-based labeling, applicable only for SharePoint. Overrides a lower-priority label unless manually applied.
  • Default sensitivity label from a policy: Always applicable for all locations. Never overrides an existing label.

Neither default is inherited from the sensitivity label applied to the SharePoint site. A site or container label configures protection settings for the workspace; files don't inherit that label or its item-level encryption and content markings. For more information, see Use sensitivity labels with Microsoft Teams, Microsoft 365 groups, and SharePoint sites.

You can supplement the library default with a content-based auto-labeling policy. The library default provides a location-based baseline without inspecting content; the policy evaluates the conditions you configure to select a label. For how these methods interact, see Will an existing label be overridden?.

When you use Office for the web to create or edit a file, the default sensitivity label for a document library can be applied without delays. However, labeling is not immediate if you upload a file or create it using Microsoft 365 Apps on Windows, macOS, iOS or Android, and then save to SharePoint:

  • File upload: it can take a few minutes for the label to be applied. | Default label from policy, lower priority | Yes | | Default label from policy, higher priority | No |

When a content-based auto-labeling policy also applies to files in the library:

  • If the policy and library default specify the same sensitivity label, the expected label remains that label. This doesn't guarantee that no labeling operations or transient failures occur.
  • If they specify different labels, the policy can replace a lower-priority automatically applied or default label, including a library default. The library default doesn't replace a higher-priority label or any manually applied label.
  • By default, the policy also preserves manually applied labels. Replacing a lower-priority manual label requires the policy's explicit override setting; this option doesn't change the library default's behavior. See Will an existing label be overridden?.

For failures reported by an auto-labeling policy, see Resolve auto-labeling failures in SharePoint and OneDrive files. The portal's Conflict code indicates a concurrent version or save conflict and is retried automatically. CannotOverrideCurrentLabel indicates that an existing label has equal or higher priority; the existing label takes precedence.

Requirements

  • An eligible premium subscription for library default labeling. Check the Apply default sensitivity labeling for SharePoint Document library entry in the Microsoft Purview sensitivity labeling licensing requirements, including the applicable prerequisite licenses. Manual labeling entitlement alone doesn't establish entitlement to this feature.
  • You've created and published sensitivity labels that include the label scope of Files & other data assets and these labels are published to the users who will select a default sensitivity label for a SharePoint document library.
  • You've enabled sensitivity labels for Office files in SharePoint and OneDrive. To check this status, you can run (Get-SPOTenant).EnableAIPIntegration from the SharePoint Online Management Shell to confirm the value is set to True.
  • To support sensitivity labels for PDFs, you've added support for PDFs in SharePoint. To check this status, you can run (Get-SPOTenant).EnableSensitivityLabelforPDF from the SharePoint Online Management Shell to confirm the value is set to True.
