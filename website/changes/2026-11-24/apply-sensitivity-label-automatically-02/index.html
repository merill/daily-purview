Apply Sensitivity Label Automatically

24 November 2026Doc updateAction required+16 / −3 lines

In brief

The page now directs administrators to the current per-SKU licensing matrix, explains license requirements by shared-location role, and documents how auto-labeling interacts with library defaults and existing labels. It also adds guidance for interpreting policy failure codes.

What Purview admins need to know

Verify applicable licenses before configuring auto-labeling, especially for SharePoint owners and members, and use the documented precedence and failure-code guidance when troubleshooting.

The configurable setting for auto-labeling policies is on the Additional label settings page.

The same precedence rules apply when a content-based auto-labeling policy evaluates files in a SharePoint library with a default label. A policy can replace a lower-priority library default label. The library default doesn't replace a higher-priority label or any manually applied label.

If both specify the same label, the expected label remains unchanged. Labeling operations or transient failures can still occur. See Library default labeling and existing labels.

For policy failures, use the code reported in the portal rather than assuming a precedence problem. The documented Conflict code indicates a concurrent version or save conflict and is retried automatically; CannotOverrideCurrentLabel indicates that the existing label has equal or higher priority. See Resolve auto-labeling failures in SharePoint and OneDrive files.
