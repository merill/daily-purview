Dlp Microsoft365 Copilot Location Learn About

10 November 2026Feature update+45 / −38 lines

In brief

The documentation updates the location name to “Microsoft Copilot, Copilot Chat, and Copilot Cowork” and adds Cowork to setup guidance, examples, and supported experiences.

What Purview admins need to know

Administrators configuring DLP policies should account for Cowork when selecting this location and defining sensitive-data controls. No mandatory action is stated.

Permissions

Accounts with one of the following roles or role groups can create or edit a DLP policy for the Microsoft 365Copilot, Copilot Chat, and Copilot ChatCowork location:

  • Microsoft Entra AI Admin - Role for managing all aspects of Microsoft 365 Copilot and AI-related enterprise services in Microsoft 365.
  • Purview Data Security AI Admin - Role for editing Data Loss Prevention policies related to Copilot and viewing AI content in Data Security Posture Management. This role doesn't have access to read prompts and responses of AI interactions.
  1. Sign in to the Microsoft Purview portal.
  2. Go to Data Loss Prevention > Policies and select + Create policy.
  3. Select the Custom template, then Custom policy.
  4. On the Locations page, set the Microsoft 365Copilot, Copilot Chat, and Copilot ChatCowork location to on.
  5. Add a rule with the Content contains > Sensitive information types condition and choose the SITs you want to detect.
  6. In the same rule, set the action to Prevent Copilot from processing content > Performing Web Searches.
  7. Save and turn on the policy.

Block SITs in web search use case example

Contoso wants employees to use Microsoft 365 Copilot or Cowork for productivity, but doesn't want sensitive customer data sent to external web search providers when Copilot grounds responses on the web.

To meet this business need, Contoso configures a DLP policy as follows:

  1. Targets the Microsoft 365Copilot, Copilot Chat, and Copilot ChatCowork policy location.
  2. Adds a rule with the Content contains > Sensitive information types condition that detects the SITs representing sensitive customer data.
  3. Sets the rule action to Prevent Copilot from processing content > Performing Web Searches.

Block SITs in prompts use case example

Contoso encourages their employees to use Microsoft 365 Copilot or Cowork to enhance productivity, but they don't want their users placing Canada physical addresses or EU debit card numbers into prompts.

To meet this business need, Contoso creates a DLP policy that targets the Microsoft 365Copilot, Copilot Chat, and Copilot ChatCowork location and has a rule that uses the Content contains > Sensitive information types > Canada physical addresses or EU debit card numbers condition to identify prompts that contain those SITs. The actions in the rule are configured to Restrict Copilot from processing content > Processing prompts.

When a user attempts to submit a prompt that contains either of these sensitive information types, they receive a message indicating that the request can't be completed because it contains sensitive information that the organization has blocked Microsoft 365 Copilot or Cowork from using.

Files uploaded in prompts

You can upload files when you craft a prompt for Microsoft 365 Copilot and Cowork to analyze. DLP can't scan the contents of files that you upload directly into prompts, so evaluation of the uploaded file for sensitive data doesn't occur. DLP only checks the text you type into the prompt itself.

Note

All Microsoft 365 Copilot prompts run in the security context of the user who initiates the prompt. This means for a user to see an item in a prompt response, they must first have the necessary permissions to access the content of the item. You can then use the Microsoft 365Copilot, Copilot Chat, and Copilot ChatCowork policy location feature to exclude items from being processed in the response summary.

In Word, Excel, and PowerPoint the Microsoft 365Copilot, Copilot Chat, and Copilot ChatCowork policy to prevent Copilot from processing content is evaluated at file open. If a sensitivity label is applied mid-session, the policy will be enforced starting the next time the file is opened.

Customize the link in Copilot policy tips

To customize the link:

  1. Create or edit a DLP policy for the Microsoft Copilot, Copilot Chat, and ChatCopilot Cowork location.
  2. In the rule's user notification settings, turn on Policy Tips.
  3. Select Provide a compliance URL for the end user to learn more about your organization's policies.
  4. Enter the full URL of the existing page, including https:// and the domain name. For example, enter https://contoso.sharepoint.com/sites/compliance/data-handling, not /sites/compliance/data-handling.

When the rule blocks an interaction, the Learn about access restrictions link opens the page that you specified. Only the link destination changes. The standard Copilot block message, the link text, and the DLP enforcement action remain unchanged. If you don't configure a compliance URL, the link continues to open Microsoft Learn.

Note

Customizing the link in Copilot policy tips isn't yet supported for Cowork.

Tip

  1. In the Microsoft Purview portal, go to Data Loss Prevention > Policies and select + Create policy.
  2. Select the Custom template, then Custom policy, and enter a name and description.
  3. On the Admin units page, select the administrative units for the policy.
  4. Select the Microsoft Copilot, Copilot Chat, and ChatCopilot Cowork location and choose the users and groups to include or exclude within the selected administrative units.
  5. Configure the rule conditions and actions, review the settings, and save the policy.

An administrative unit restricted administrator can select only their assigned units and manage policies within that scope. An unrestricted administrator can scope policies to administrative units or keep Full directory to apply a policy across the organization. Existing tenant-wide policies continue to apply; using administrative units is optional.

Important

Copilot DLP policy scoping for Microsoft 365 Copilot, Copilot Chat, and Cowork is based on the user who submits the prompt, not the owner of a file or email that Copilotthe experience accesses. For example, a policy scoped to the Finance administrative unit applies to Finance users' Copilot and Cowork interactions, even when they access content owned by someone outside Finance. Other applicable DLP policies continue to apply.
